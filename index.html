FieldOps Incident Portal
GitHub SDLC 운영 가이드

이 문서는 현장 장애 접수, 우선순위 분류, 복구 이력 관리를 담당하는 내부 포털을 기준으로 Plan부터 Models까지 SDLC 8단계 운영 기준을 정리합니다.

서비스: 장애 접수/복구 워크플로 보안: GHAS + Required checks 운영: Incident runbook + MTTR

도메인 가정

FieldOps Incident Portal은 관제팀과 현장 엔지니어가 사용하는 내부 웹 서비스라고 가정합니다. 목표는 기능 개발 속도보다 장애 대응 신뢰성과 감사 가능성을 확보하는 것입니다.

SDLC 8 Stages

카드를 클릭하면 해당 단계의 FieldOps 운영 케이스가 표시됩니다.

GitHub에서 직접 보여줄 SDLC 케이스

아래 케이스는 저장소 탭(Issues, Pull Requests, Actions, Security)에서 바로 시연 가능한 항목입니다.

  1. Plan: 이슈 템플릿으로 장애 분류/수용기준 등록
  2. Code: 브랜치 생성 후 복구 로직 수정 커밋
  3. Review & Test: PR에서 CODEOWNERS + Required checks 확인
  4. Build & Deploy: Actions 로그에서 빌드/스모크 테스트 결과 확인
  5. Operate: incident 라벨 이슈로 복구 타임라인 기록
  6. Modernize: 노후 API 교체 작업을 PR 시리즈로 분할
  7. Govern: 예외승인 템플릿과 라벨 정책 검토
  8. Models: 작업 등급별 모델 사용 정책 점검
