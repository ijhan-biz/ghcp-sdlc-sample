GitHub-native SDLC GHAS 5-layer DDD + BDD Go / No-Go

0) 데모 시작 링크

아래 링크를 순서대로 열어두면 발표 중 전환이 빠릅니다.

Seed SDLC Workflow SDLC Issues Demo PR List Dependency Review Workflow Dependency Review Example Run Security Overview

완료 기준: 탭 6개를 미리 열고 발표 순서대로 좌우 이동만 하면 됩니다.

1) 10분 스크립트 (핵심)

  1. Actions seed 실행 결과를 열고 8단계 이슈가 자동 생성됨을 보여준다.
    "개발 작업은 채팅이 아니라 GitHub 증거로 남깁니다. SDLC 8단계가 이슈로 기록됩니다."
  2. Issues `label:sdlc-stage` 목록에서 Plan과 Govern 이슈를 1개씩 연다.
    "AI에 맡기기 전, 리더 질문과 멈춤 기준을 먼저 합의합니다."
  3. PR 데모 PR 목록에서 open PR 하나를 열어 required checks를 보여준다.
    "AI PR은 완성이 아니라 리뷰 요청입니다. 승인 경계는 사람과 체크입니다."
  4. GHAS Dependency Review workflow와 example run을 연다.
    "실패 로그는 우회 대상이 아니라 다음 입력입니다. 이 화면이 보안 게이트 증거입니다."

2) 15분 스크립트 (권장)

  1. 10분 스크립트 전체를 실행한다.
  2. Security 탭에서 Overview를 열고 `SECURITY.md` 정책 링크로 이동한다.
    "AI 변경이 늘수록 보안은 더 앞단으로 와야 합니다. 정책과 실행 화면을 같이 보여드립니다."
  3. GHAS 5-layer 문서(`docs/ghas-setup.md`)를 열어 5중 방어선을 설명한다.
    "Code review, CodeQL, Secret scanning, Enterprise controls, Agent governance를 한 운영 체계로 묶습니다."
  4. 마지막에 `docs/preflight-checklist.md`로 Go/No-Go 기준을 보여준다.
    "오늘 데모는 이벤트가 아니라 파일럿 승인 회의의 입력입니다."

3) 25분 스크립트 (심화)

  1. 15분 스크립트를 완료한다.
  2. DDD 코드(`src/domain`, `src/application`, `src/infrastructure`)를 열어 경계 분리를 설명한다.
  3. tool exception 템플릿과 Govern 이슈를 연결해 예외 승인 체계를 시연한다.
  4. slo-monitor 이슈와 cost-governance 문서를 열어 운영/비용 루프를 설명한다.
    "비용은 금지가 아니라 라우팅과 승인으로 통제합니다."

4) 장애 대비 Fallback

  • Actions 지연: `docs/sdlc-stage-evidence-map.md` 먼저 제시
  • Security 권한 부족: `SECURITY.md` + `docs/ghas-setup.md`로 대체
  • PR 없음: `pull_request_template.md`와 `CODEOWNERS` 파일 직접 오픈
